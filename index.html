// 03 · encrypt with sequoia

Post-quantum encryption needs a post-quantum tool

Browser WebCrypto has no X448/Ed448 and no composite-KEM combiner, so this page won't pretend to encrypt to a PQC key in-tab. Instead it hands you the exact sq workflow — honest and interoperable.

  • Hybrid by construction. The session key is derived from both ML-KEM-1024 and X448. An attacker must break both — a quantum computer threatens the classical half; a flaw in ML-KEM would leave X448 standing.
  • Harvest-now-decrypt-later resistant. Traffic captured today stays sealed against a future cryptographically-relevant quantum computer.
  • Use Sequoia or rpgp. GnuPG's Kyber composites are a different, incompatible scheme — it cannot encrypt to this certificate.

// 04 · import & verify

Trust the fingerprint,
not the webpage

Anyone can host a page claiming to be me. What makes this certificate trustworthy is the fingerprint matching one you got somewhere else — and a lint pass from a PQC-capable implementation.

01

Get the cert

Download key.asc or copy the armored block. Both contain identical bytes, CRC-24 included.

02

Lint & compare

Run sq cert lint to check self-signatures and expiry, then compare all fingerprint characters against a second channel.

03

Import & use

Add it to your Sequoia cert store and encrypt. In-browser signature verification of ML-DSA/Ed448 isn't available, so let sq do the cryptographic checking.

Human-readable dump of every packet, algorithm, and subpacket — the same structure shown in the inspector above:

sq inspect key.asc

Validates self-signatures, revocations, expiry, and algorithm strength. This is the cryptographic check the browser can't perform for PQC keys:

sq cert lint key.asc

Add the certificate to your local Sequoia cert store so sq encrypt --for <FPR> can find it:

sq cert import key.asc

Fetch from this site and import in one go. Commit key.asc next to index.html for this to work.

curl -fsSL https://your-name.github.io/your-repo/key.asc -o key.asc && sq cert import key.asc
A fingerprint shown on the same page as the key proves nothing by itself. The second channel is the whole point.
// 05 · publish your own

Make this page yours

One file, one edit, zero build steps. Fingerprint, randomart, QR, packet inspector and commands all re-derive from whatever certificate you paste in.

1

Export your public certificate

From your Sequoia keystore. Piping through sq packet armor produces paste-able ASCII armor on every sq version:

sq cert export --cert <FINGERPRINT> | sq packet armor > key.asc

No PQC key yet? Generate one with Sequoia and pick the ML-KEM-1024+X448 / ML-DSA-87+Ed448 cipher suite — see sq key generate --help for the profile and cipher-suite flags in your version.

2

Paste it into this file

Open index.html, find the EDIT ME banner at the top of the script, and paste everything — BEGIN line to END line — between the backticks. That's the only required change.

const PGP_PUBLIC_KEY = `-----BEGIN PGP PUBLIC KEY BLOCK----- …your exported cert, every line… -----END PGP PUBLIC KEY BLOCK-----`;
3

Push & switch on Pages

Commit index.html → Settings → Pages → Deploy from a branch → main · /(root). About a minute later your key is live, and the curl command on this page updates itself to the real URL.

4

Ship key.asc & post the fingerprint

Commit the downloaded key.asc next to index.html so curl … | sq cert import works. Then publish the fingerprint on your socials — that's the second channel people verify against.
